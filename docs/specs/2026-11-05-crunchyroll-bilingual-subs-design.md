# Crunchyroll 双语字幕翻译插件 — 设计文档

日期：2026-11-05
状态：用户已确认（2026-11-05）

> 用户是 Crunchyroll 付费会员，无广告，暂停/自动播放逻辑不需要识别广告。

## 1. 目的与背景

用户在 Chrome 上用 Crunchyroll 看番，希望看到 **中文 + 原字幕的双语对照**。Crunchyroll 不提供中文字幕，所以插件要把播放器当前选中的字幕（通常是英文）翻译成目标语言（默认简体中文），并和原文一起显示。

翻译主力是大模型 API（当前用 DeepSeek 的 flash 模型），比机翻更通顺，也能利用上下文保持人名、称呼、语气一致。大模型失败时自动回退到谷歌免费机翻，保证始终有译文。

## 2. 目标

- 在 Crunchyroll 播放页上，字幕以双语对照显示：译文在上、原文在下，译文字号略大（位置、字号可调）。
- **稳定优先**：开播检测到字幕后**先暂停视频**，等第一批（约前 30 句）翻译完成后自动继续播放。之后不出现"先显示 A 译文、再换成 B 译文"的跳变。
- 剩余字幕在后台分批翻译，优先翻译当前播放位置附近和之后的内容（拖进度条后同样优先）。
- 翻译请求带上前后文和番名/集名，帮助模型统一专有名词译法。
- 某一批大模型翻译失败（超时、HTTP 错误、额度不足、返回格式不对、行数对不上），该批**自动改用谷歌免费机翻**。
- 每集译文**缓存在本地**，重看或拖进度条时直接使用，不重复调用 API。
- 默认目标语言简体中文，可在设置中改为其他语言。
- 播放器上有一个小开关，可切换：双语 / 仅译文 / 关闭（只看原字幕）。
- 模型供应商与模型可更换：当前预设 DeepSeek，同时支持任意 **OpenAI 兼容接口**（自定义 Base URL、API Key、模型名、额外请求参数）。

## 3. 非目标

- 不上架 Chrome 应用商店，只在用户自己的 Chrome 上以"开发者模式 → 加载已解压的扩展程序"使用。
- 不支持 Firefox、Safari 等其他浏览器（Edge 能用最好，但不专门适配）。
- 不做多账号同步、云端缓存。
- 不翻译 Crunchyroll 网站界面，只翻字幕。
- 暂不实现非 OpenAI 兼容格式的接口（例如 Anthropic 原生格式），但代码结构上要能后续加。

## 4. 反目标（技术上能跑但算失败的情况）

- 播放中字幕频繁闪动、跳变，或译文明显晚于原文出现。
- 为了翻译导致视频卡顿、掉帧，或者破坏 Crunchyroll 原有的字幕样式和特效字幕（招牌、标题等）。
- 每看一集都重复花钱翻译同一份字幕。
- API Key 被发送到配置的接口以外的任何地方。
- 大模型挂了就没有中文。

## 5. 约束与已知事实

- 平台：Chrome，Manifest V3 扩展。
- DeepSeek（2026-11 官方文档）：
  - OpenAI 兼容 Base URL：`https://api.deepseek.com`，接口 `/chat/completions`。
  - flash 模型名：`deepseek-flash`（旧名 `deepseek-v4-flash` 仍可用）。
  - **思考模式默认开启**，必须在请求体加 `"thinking": {"type": "disabled"}` 关闭。字幕翻译不需要思考模式。
  - 价格很低（flash 输入约 $0.15/百万 token，输出 $0.6/百万 token），并发上限高，可以并行发多批。
- 谷歌免费机翻：使用无需 Key 的公开接口（如 `translate.googleapis.com/translate_a/single?client=gtx...`）。这个接口不官方，可能限流或变动，所以只作为兜底。
- 用户网络：系统代理走 v2rayN（10808）。扩展的请求走 Chrome 的代理设置，DeepSeek 和谷歌都需要能访问到；插件本身不处理代理。
- Crunchyroll 字幕：播放器加载一集时会请求一份播放信息（JSON），里面包含各语言字幕文件的地址；常规字幕是 **ASS 格式**，由播放器内的 ASS 渲染器（libass 一类）画在视频上。字幕可能在 iframe 里的播放器中加载。具体接口地址和播放器结构需要构建时在真实页面上确认（见第 8 节）。

## 6. 已确定的设计决策（用户确认）

1. 显示形式：双语对照。
2. 开播体验：稳定方案，先暂停等第一批译文，再自动播放；不做"先机翻、后替换"。
3. 默认目标语言：简体中文，可改。
4. 模型：当前只用 DeepSeek flash，非思考模式；但必须保留更换供应商、接口、模型的能力。
5. 回退：大模型失败时自动回退谷歌免费机翻。
6. 以下我提出、用户同意的功能也要做：译文在上原文在下、带番名做上下文、本地缓存、播放器上的模式开关、额外请求参数（用于其他供应商关闭思考等）。

## 7. 功能细节

### 7.1 设置页（扩展选项页 + 弹出窗口）

- **供应商预设**：DeepSeek（默认）、自定义 OpenAI 兼容。选择预设后自动填好 Base URL、模型名、额外参数，用户可修改。
  - DeepSeek 预设：Base URL `https://api.deepseek.com`，模型 `deepseek-flash`，额外参数 `{"thinking": {"type": "disabled"}}`。
- **API Key**：存在 `chrome.storage.local`（本机，不同步）。
- **模型名**：自由填写。
- **额外请求参数**：JSON 文本框，合并进请求体（例如其他供应商的 `enable_thinking: false`）。
- **目标语言**：下拉选择，默认简体中文。
- **"测试连接"按钮**：发一句测试翻译，显示成功或错误信息。
- **显示设置**：双语 / 仅译文 / 关闭；译文在上或在下；译文字号缩放。
- **缓存管理**：显示已缓存集数和占用空间，提供"清空缓存"。
- 弹出窗口（点击扩展图标）：总开关、当前集的翻译进度（已完成多少句，哪些批次用了谷歌回退）、"重新翻译本集"。

### 7.2 字幕获取

> **实测更新（2026-11-05）**：Crunchyroll 网页端（Bitmovin 播放器，无 iframe）默认播放**硬字幕视频流**（`playback/v4/{id}/web/chrome/play` 返回的 `hardSubs[lang].url`），不会加载 ASS 文件；同一响应的 `subtitles[lang]` 里有 ASS 地址（`format: "ass"`）。因此采用：把播放器改为播放干净流（`json.url`），由插件自绘全部字幕——对白双语自绘，特效行用 ASS.js 原样渲染。第 7.5 节"改写 ASS 交给播放器渲染"的方案不可行，按备选方案执行。


- 拦截 Crunchyroll 播放器加载的字幕文件（或从播放信息 JSON 中取到当前选中字幕的地址后自行下载）。
- 解析 ASS：取出 `Dialogue` 行，记录时间、样式、文本；去掉 `{...}` 覆盖标签得到纯文本用于翻译，`\N` 视为换行。
- 用户在播放器里切换字幕语言、换集（站内是单页应用，不刷新页面）时，要重新识别并处理。
- **只支持 ASS 字幕（我的决定）**：第一版只处理 ASS。遇到 WebVTT/TTML（配音版的 CC 字幕）或没有字幕轨（硬字幕）时，不暂停、不翻译，在播放器上短暂提示"此字幕格式暂不支持"。代码上把"解析"和"显示"分开，方便以后加 VTT。

### 7.3 翻译流程

- 把对白按时间顺序切成批次，每批约 30～40 句。
- 第一批完成前保持视频暂停，并在播放器上显示"正在翻译…"提示；第一批完成（或回退谷歌完成）后自动播放。
  - 如果第一批大模型和谷歌都失败，也要恢复播放，并提示"翻译失败，仅显示原字幕"，不能让视频一直卡住。
- 其余批次并发翻译（并发数可配置，默认 4～6）。
- **术语表（我的决定）**：并行批次拿不到上一批的译文，所以人名、称呼的一致性靠术语表保证。开播时和第一批**同时**发起一个"术语提取"请求：把整集对白原文发给模型，让它列出人名、地名、称呼、专有名词及其译法。第一批不等术语表；第二批起的所有批次都带上术语表。术语表失败就不带，不影响翻译。术语表随该集缓存。
- 每个请求包含：系统提示（翻译要求、目标语言、保持行号、输出格式）、番名/集名、术语表、本批前后各若干句**原文**作为上下文（只读，不翻译）、本批带编号的句子。
- 要求模型按编号返回 JSON（或逐行带编号的文本），解析后校验行数和编号；对不上视为失败，走谷歌回退。
- 单批超时（默认 30 秒）或报错时：同一批先用大模型重试 1 次，仍失败则改用谷歌。
- 拖进度条时，把目标位置附近尚未翻译的批次提到队列最前。若拖到的位置还没翻译完，**只显示原文**，等这一批到了再出现译文（不暂停、不用机翻顶替）。

### 7.4 特效字幕（招牌、标题、歌词等）

- 有定位、绘图标签的行，或明显属于"招牌/OP/ED"样式的行，**默认不翻译、保持原样**，避免画面上出现大量错位的中文。
- 普通对白才做双语。

### 7.5 显示

- 双语显示时，原字幕的样式（字体、描边、位置）应尽量和 Crunchyroll 原有效果一致，译文用匹配的样式显示在原文上方。
- 推荐做法（构建者可在实测后调整）：直接**改写 ASS 文本**，把每条对白改成 `译文\N原文`，并给译文加字号覆盖标签，再交给播放器原有的渲染器画出来。这样特效字幕、定位、描边都不受影响，也不需要自己做时间同步。
  - 如果播放器不方便替换字幕内容，再考虑在视频上叠一层自己的字幕层，按 `video.currentTime` 同步显示，并隐藏原字幕的对白部分。
- 模式开关（双语 / 仅译文 / 关闭）放在播放器控制栏附近，切换后立即生效。
- **两个开关的区别（我的决定）**：
  - 弹出窗口的**总开关**关闭 = 插件完全不工作：不翻译、不暂停、不改字幕。
  - 播放器上的"关闭"模式 = **只影响显示**：翻译照常在后台进行并缓存，随时切回双语都能立即看到。开播仍会暂停等第一批，因为切回双语时要保证有译文。

### 7.6 缓存

- 缓存键：集 ID + 字幕语言 + 目标语言 + 字幕内容哈希。
- 内容：每句译文，以及每句是来自大模型还是谷歌。
- 用 `chrome.storage.local`（申请 `unlimitedStorage`）或 IndexedDB。
- 大模型和谷歌回退的译文都缓存，每句标记来源。
- **重看时（我的决定）**：缓存里的谷歌译文**照常使用**，不自动重翻（避免再花钱，也避免播放中途换字幕）。弹窗里的"重新翻译本集"默认**只重翻谷歌回退的句子**，另提供"全部重翻"选项。

## 8. 留给构建者决定的部分

- Crunchyroll 播放器的具体结构（是否在 iframe 中、字幕接口地址、使用哪个 ASS 渲染器），需要在已登录的真实播放页上实测确认，再决定拦截方式。
- 7.5 中"改写 ASS"与"自绘字幕层"二选一，以实测可行性为准。前者是首选。
- 批次大小、并发数、上下文句数、超时的具体默认值。
- 提示词的具体措辞。
- 代码组织（是否用构建工具）。用户只在本机使用，无构建步骤的纯 JS 也可以。
- 特效字幕的判定规则细节。

## 9. 验收标准

- 在 Crunchyroll 播放一集英文字幕的番：开播暂停，几秒内自动开始播放，第一句对白就有中文。
- 全程中文出现时机和原文一致，没有闪动或替换。
- 断网或填错 API Key 时：大模型失败，自动用谷歌翻译，弹窗里能看到"已回退谷歌"的批次数。
- 第二次打开同一集：不再请求 DeepSeek（可在弹窗或开发者工具里确认），直接出字幕，也不需要暂停等待。
- 在设置里换成其他 OpenAI 兼容供应商和模型后能正常翻译。
- 播放器上的模式开关能在双语、仅译文、关闭之间切换。
- 换集、切换字幕语言后能自动重新处理。
